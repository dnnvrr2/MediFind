# GitHub collaboration workflow

Use a separate branch for each project task so changes can be reviewed before they reach `main`.

1. Update your local `main` branch with the latest project changes.
2. Create a branch named for yourself and the task, such as `yourname/medicine-search`.
3. Make a focused project change and review the files you changed. Keep passwords, API keys, local environment files, and private uploads out of commits.
4. Commit the change with a short, specific message that describes the result.
5. Push your branch to the shared GitHub repository and open a pull request targeting `main`.
6. Ask a groupmate to review the pull request, respond to their feedback, and merge only after the group is ready.

After the pull request is merged, update local `main` before starting the next task.
